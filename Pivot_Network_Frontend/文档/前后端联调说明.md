# 前后端联调说明（V2.1 本机演示）

> 目标：在**不依赖 Docker、不部署**的前提下，让前端页面真实调用 FastAPI 后端，
> 走通「登录 → 浏览资源 → 下单 → 激活订单 → 兑换授权码 → 拿到 RuntimeSession → 心跳/停止」
> 这条业务主链，并保证没有后端时页面仍可完整演示（自动回退 mock）。

## 一、两种运行模式

| 模式 | 启动方式 | 数据来源 | 适用场景 |
|---|---|---|---|
| **mock（默认）** | `npm run dev` / `npm run build` | 前端 `src/services/mock/platform.mock.ts` | 无后端时演示全部页面与交互 |
| **真实后端** | `npm run dev:real` / `npm run build:demo` | `http://127.0.0.1:8000/api/v1` | 答辩演示真实业务链路 |

模式由环境变量控制（见 `Pivot_Network_Frontend/.env.demo`）：

```dotenv
VITE_USE_MOCK=false
VITE_API_BASE_URL=http://127.0.0.1:8000
VITE_DEMO_EMAIL=demo@pivot.local
VITE_DEMO_PASSWORD=demo1234
```

`VITE_USE_MOCK !== 'false'` 时一律使用 mock；真实模式下后端不可达会自动回退 mock 数据，
页脚显示「后端异常 · 已回退演示数据」，不会白屏。

## 二、前端改造

```text
src/services/api/
├── client.ts    # 基础层：BASE_URL + /api/v1、Bearer Token、超时、ApiError、mock 开关
├── auth.ts      # 演示账号自动登录（登录失败自动注册）、token 持久化、ensureAuth()
├── mappers.ts   # 后端 snake_case payload → 前端领域模型（所有字段差异收敛在这一层）
├── offers.ts    # GET /offers、GET /offers/{id}
├── nodes.ts     # GET /platform/nodes、GET /platform/swarm/overview、趋势派生
├── orders.ts    # POST /orders、POST /orders/{id}/activate
├── grants.ts    # GET /me/access-grants/active、POST /access-grants/redeem(-by-code)
└── sessions.ts  # GET /runtime-sessions/{id}、heartbeat、stop
```

- **映射层**：后端把算力规格放在 `price_snapshot / capability_summary / inventory_state` 三个自由 JSON 里，
  前端 `Offer` 是平铺字段，`mappers.ts` 负责派生 `gpu / cpu / memory / price / tags / latency / region`；
  `RuntimeSession` 的 snake_case 字段（`connect_metadata`、`wireguard_lease_metadata` 等）也在这里转成页面模型。
- **store**：`offers / monitor / session` 改为真实 API + 失败回退；新增 `connection` store 统一记录连接状态。
- **启动引导**：`App.vue` 在真实模式下先 `ensureAuth()` 自动登录演示账号，再 `restoreActiveSession()`
  从 `GET /me/access-grants/active` 恢复最近一次会话，因此刷新页面不会丢失会话。
- **下单链路**：`offers.createOrder` → `session.createSession`：
  `POST /orders` → `POST /orders/{id}/activate` → `POST /access-grants/redeem-by-code`
  → 用返回的 `RuntimeSessionRead` 渲染会话中心；失败时 Toast 展示后端错误原文，抽屉保持打开。

## 三、后端本机演示（backend-demo 交付）

后端无 Docker 启动方式见 [Pivot_Network_Backend/Plantform_Backend/docs/LOCAL_DEMO.md](../Pivot_Network_Backend/Plantform_Backend/docs/LOCAL_DEMO.md)，要点：

- PostgreSQL 用 pip 包 `pgserver` 以 rootless 方式运行，走 Unix socket，不占用 TCP 端口；
- `BACKEND_DEMO_MODE=true` 时 `deps.get_adapter_client()` 返回 `DemoAdapterClient`（进程内模拟
  swarm 节点与 runtime bundle），因此没有 8010 端口的 Swarm Adapter 也能完成兑换；
- 种子数据：3 个 offer（`offer-a100-80g-tianjin` ¥42/h、`offer-rtx4090-beijing` ¥18/h、`offer-l40s-shanghai` ¥26/h）、
  4 个节点、买家 `demo@pivot.local / demo1234` 与 3 个卖家账号；
- CORS 放行本机前端端口（5173/5174 及任意 loopback 端口），支持 Bearer 凭证。

```bash
# 后端
cd Pivot_Network_Backend/Plantform_Backend
export PIVOT_PYTHON=/tmp/pivot-be-venv/bin/python
bash scripts/start_local_demo.sh      # 起 DB → 迁移 → 种子 → uvicorn :8000

# 前端（另一个终端）
cd Pivot_Network_Frontend
npm run dev:real                      # → http://127.0.0.1:5173（真实后端模式）
```

## 五、已知边界（演示级，非缺陷）

1. **GPU/CPU 负载与趋势图为演示派生值**：后端节点接口只给调度状态（ready/warning、running_tasks），
   真实利用率来自 Docker Swarm Adapter 的监控采集，本机未接入，`mappers.ts` 用节点 id 哈希稳定派生。
2. **算法模板仍在本地**：后端暂无算法模板接口，`/algorithms` 与下单时的算法选择使用前端模板数据。
3. **卖家上架为本地流程**：`/seller` 表单提交只写本地草稿列表，未调用后端 onboarding 接口。
4. **demo adapter 的 bundle 为合成数据**：已 closed 的会话再次 redeem 会被 inspect 成 running（演示可接受）。
5. **pgserver 数据在 `/tmp`**：机器重启后需重新执行 `start_local_demo.sh`（数据不丢；`/tmp` 被清理会自动重建）。

## 六、排错

| 现象 | 处理 |
|---|---|
| 页脚显示「后端异常 · 已回退演示数据」 | 后端未启动：`bash scripts/start_local_demo.sh`，确认 `curl http://127.0.0.1:8000/api/v1/health` |
| 浏览器控制台 CORS 报错 | 前端端口需在本机 loopback 范围；后端已放行任意 `127.0.0.1/localhost` 端口，若仍报错重启后端 |
| 下单 401 | token 过期：清 localStorage 后刷新页面，`ensureAuth()` 会重新登录 |
| 刷新后会话消失 | 该会话已 stop/close：`GET /me/access-grants/active` 不再返回未结束授权，属预期 |
